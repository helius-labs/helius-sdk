## [Unreleased]

### Added

- **Pre Confirmations** (`preconfSubscribe`): new standalone `makePreconfWsClient` / `makePreconfWsClientForApiKey` (`helius-sdk/websockets/preconfWs`) for Helius's lowest-latency transaction stream, delivering scheduled transactions over WebSocket before they are shredded. Served from the Gatekeeper endpoint `wss://beta.helius-rpc.com/?api-key=<KEY>`. Yields an `AsyncIterable` of `PreconfNotification { version, slot, transactionIndex, status, transaction, transactionBytes }` — the bincode `VersionedTransaction` is decoded into a `@solana/kit` `Transaction` and the raw bytes are also exposed. Notifications are **binary** frames (the subscribe ack is a JSON text frame); the little-endian layout is `version:u8 | slot:u64_le | transaction_index:u64_le | status:u8 | bincode(VersionedTransaction)`. The `version` byte is checked first (currently `1`; unknown versions are dropped) and `status` is exposed as the `PreconfStatus` enum (`Failed = 0`, `Success = 1`, `Unknown = 2`). Subscribe takes no filters (streams all scheduled transactions); pricing is credit-based (10 credits per notification). Includes `decodePreconfFrame`, `PreconfStatus`, `PRECONF_WIRE_VERSION`, tests, and `examples/websockets/preconfSubscribe.ts`. A pre-confirmation is an early signal, not a guarantee; coverage is not continuous (scales with stake forwarding to Helius — expect gaps).
- **`sendBundleWithSender()`**: submits an ordered bundle of pre-signed transactions (max 5) over Sender Max via the `sendBundle` method, then tracks landing per-signature with `getSignatureStatuses` (no Jito bundle IDs). At least one transaction must carry the 0.001 SOL Sender Max minimum tip.

### Changed

- **BREAKING (defaults): Sender tip tiers.** The non-SWQOS tier is now branded **Sender Max** (`swqosOnly: false`) with a minimum tip of **0.001 SOL** (`MIN_TIP_LAMPORTS_MAX = 1_000_000n`); the previous 0.0002 SOL tier is removed. SWQOS-only (`swqosOnly: true`) is **0.000005 SOL** (`MIN_TIP_LAMPORTS_SWQOS`), corrected from a prior `500_000n` value to `5_000n`. `determineTipSol`, `createSmartTransactionWithTip` (default tip), and `sendTransactionWithSender` now use the Sender Max floor. Sender doc comments describe routing generically (multiple high-speed pathways + priority auction) rather than enumerating Jito/SWQOS layers.
- `sendTransactionWithSender` / `sendViaSender` now accept a caller-controlled `skipPreflight` option (default `true`) instead of forcing preflight off; Sender no longer requires `skipPreflight: true` or a mandatory priority fee, and the doc comments were softened accordingly.

### Deprecated

- `MIN_TIP_LAMPORTS_DUAL` is deprecated in favor of `MIN_TIP_LAMPORTS_MAX`. It remains as a backward-compatible alias now resolving to 0.001 SOL (not the removed 0.0002 SOL value).

### ⚠️ Breaking Changes

- **`@solana/kit` v5 → v6 and `@solana-program/*` peer bumps** ([#322](https://github.com/helius-labs/helius-sdk/pull/322)). Consumers must upgrade their own `@solana/kit` install to a compatible v6 line. This is the change that drives the major version.
- **Webhooks + enhanced-transactions REST host migrated to `api-mainnet.helius-rpc.com`** ([#328](https://github.com/helius-labs/helius-sdk/pull/328)). Any infrastructure pinning to the old `api.helius.xyz` host (egress allowlists, proxies, fixtures) needs updating.
- **Legacy auth helpers removed** ([#314](https://github.com/helius-labs/helius-sdk/pull/314)): `agenticSignup`, `executeCheckout`, `executeUpgrade`, `executeRenewal`, `signupFunding`, the sponsored `PaymentMode`, and the `AgenticSignupOptions` / `AgenticSignupResult` / `CheckoutResult` / `CheckoutRequest` types. Use `signup`, `signupAndPay`, `upgradePlan`, and `payRenewal` ([#298](https://github.com/helius-labs/helius-sdk/pull/298), [#312](https://github.com/helius-labs/helius-sdk/pull/312)).
